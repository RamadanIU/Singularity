# Многомодульная Singularity: самодообучение с ростом нейронов, оркестратор с экспертами, мышление с наградой за целостность

**Коротко.** Владелец предложил три идеи. Здесь разобрано, что из них уже есть в науке, что в них новое и что можно
сделать. Часть сразу проверена на нынешней `mini2` (36 млн параметров, 8 МБ) прямо на процессоре.

| Идея владельца | Что сделано | Что получилось (на mini2, CPU) |
|---|---|---|
| **1. «Не знаю → пришли информацию → сама себя дообучу, добавив нейроны ровно под объём»** | `self_grow.py`: модель сама задаёт себе вопросы о присланном тексте, отвечает на них, видя текст, и учит **новые** нейроны (старые веса заморожены) отвечать так же **без текста**. Растёт, пока не выучит по самопроверке без разметки. Выученное — отдельный файл-модуль (100–400 КБ) | 20 выдуманных слов, новый разговор, вопросы в формулировках, которых не было при обучении: открытые вопросы — **73% против 9%** у исходной модели (потолок «с объяснением перед глазами» — 86%). Модель сама выросла до 8 нейронов на слой для 20 слов и до 32 — для 60. Дообучение **всех** весов теми же данными хуже по всем пунктам, а обычное дообучение ломает честность (22.5% «не знаю» против 95%) и старые навыки (−48 задач из 615) |
| **2. Оркестратор, эксперты, «подключаемый мозг», многократный пропуск мысли** | `orchestrator.py`: голова на скрытых состояниях mini2 выбирает тему, модуль знаний и число кругов мышления; план эксперта по JavaScript | Тема вопроса на отложенных задачах — **85.5%** верно (просьбы про код — 100%). Модуль через оркестратор: знание сохраняется (78%), а честность и старые навыки — **как у исходной модели** (95% и 55.6% против 55.8%). Больше кругов ядра мышления нынешней mini2 **не помогают** (55–56% при 1–5 кругах): её учили на одинаковой глубине, и всю работу она делает за первый круг. Нужно дообучение со случайной глубиной |

Для игр сначала нужен эксперт по JavaScript (план и стоимость — раздел 2.5); «думать и спорить» можно проверить на логике и счёте уже сейчас |

Всё ниже — это не «нельзя», а «как сделать». Где идея ещё не проверена, написано, как её проверить и сколько это стоит.

## 0. Отправная точка

- `mini2` — 36 млн параметров, почти все троичные ({−1, 0, +1}). В вычисляющих слоях не больше ~6 МБ информации
  (31.7 млн × 1.58 бита), и почти всё это занято самим русским языком и навыками диалога
  ([TRAINING_REASONING_RU.md](TRAINING_REASONING_RU.md), раздел 2). Владелец прав: модель плотная, и **если
  дообучать её старые веса, новое будет вытеснять старое**. Это не догадка, а измерение — раздел 1.4.
- В модели уже есть «часть, которая размышляет», — ядро мышления: 2 рекуррентных слоя с общими весами, которые
  крутятся до 3 раз, а роутер решает, какому кусочку слова сколько думать.
- Модель обучена честно говорить «не знаю — объясни» и отвечать по объяснению в разговоре. Это умение оказалось
  ключом к идее 1: модель может быть **сама себе учителем**.

## 1. Идея 1: «не знаю → пришли информацию → сама себя дообучу, отрастив новые нейроны»

### 1.1. Почему просто «дообучить на присланном тексте» не работает

1. **Забывание.** Все веса плотно заняты. Если менять их ради нового факта, портится старое. Это называется
   катастрофическим забыванием (McCloskey, Cohen, 1989), и в нашем опыте оно видно в цифрах (раздел 1.4).
2. **Текст ≠ знание, которое можно достать.** Если модель просто заучит предложение «Залкута — огромный овощ красного
   цвета», она часто не ответит на вопрос «Какого цвета залкута?»: знание лежит в весах в той форме, в какой его
   показали («Physics of Language Models», часть 3.1, Allen-Zhu, Li, 2023). Нужны вопросы и ответы в разных
   формулировках. Кто их напишет? Здесь — сама модель.
3. **Ёмкость.** Новым знаниям нужно место. Владелец предложил ровно это: добавлять нейроны под объём новой
   информации.

### 1.2. Как устроено (`self_grow.py`)

```
 пользователь: «Залкута — огромный овощ красного цвета, растёт в огороде»
        │
        ▼
 ┌─ инструмент вопросов ──────────────┐     «Какого цвета залкута?», «Где растёт?», «Это овощ или рыба?», …
 └────────────────────────────────────┘
        │  вопрос + объяснение в разговоре
        ▼
 ┌─ модель-учитель (это сама mini2) ──┐     «Залкута — красного цвета.»  (видит объяснение — отвечает по нему)
 └────────────────────────────────────┘
        │  пары «вопрос → свой же ответ»
        ▼
 ┌─ модель-ученик = mini2 + НОВЫЕ нейроны ─────────────────────────────────────────────┐
 │  старые троичные веса заморожены;                                                     │
 │  к MLP всех 6 слоёв внимания добавлены k нейронов: y = MLP(x) + down(relu(up·x+b)²),  │
 │  down = 0 в начале — модель в момент вставки считает РОВНО как раньше;                │
 │  учатся только новые нейроны: отвечать так же, но БЕЗ объяснения в разговоре;         │
 │  и одновременно — на старых диалогах и на вопросах о НЕвыученных словах отвечать как  │
 │  исходная модель (KL-дивергенция к ней), чтобы не выдумывать и не забывать.           │
 └───────────────────────────────────────────────────────────────────────────────────────┘
        │
        ▼
 самопроверка без разметки: на СВОИХ отложенных вопросах угадывает ли модель без объяснения то новое, что сказал
 учитель? и не изменились ли её ответы на старое?
   нет → отрастить ещё нейронов (×2) и доучить;   да → сохранить «модуль знаний» (отдельный файл)
```

Из чего складывается «сама себя дообучает»:

- **Учитель — она сама.** Учитель и ученик — одна и та же сеть: с объяснением в разговоре (так она уже умеет
  отвечать) и без него. Знание переносится из разговора в веса. Это называется дистилляцией контекста (Snell и др.,
  2022). Внешняя большая модель не нужна.
- **Рост по требованию.** Начинаем с 2 нейронов на слой. После обучения модель проверяет себя на своих же вопросах,
  отложенных от обучения. Угадывает ли она без объяснения хотя бы 85% токенов ответа учителя, которых исходная
  модель не знала? Не изменилось ли старое: на старых диалогах и невыученных словах первый выбор должен совпадать
  с исходной моделью в ≥ 97% позиций. Если нет — нейронов становится вдвое больше. Так их получается столько,
  сколько нужно для этой информации: для 20 слов — 8 на слой, для 60 — 32 (раздел 1.5).
- **Не мешать старому.** Старые веса не меняются. Новые нейроны учатся молчать там, где их не просили: на старых
  диалогах и на вопросах о словах, которых модель не учила.
- **Подключаемый мозг.** Новые нейроны сохраняются отдельным файлом (модулем знаний). Модуль можно подключить,
  отключить или передать другому. Если подключено несколько модулей, оркестратор включает нужный (раздел 2.3).

Где тут «ровно на количество токенов». Грубая оценка ёмкости: языковая модель хранит не больше ~2 бит знаний на
параметр (Allen-Zhu, Li, 2024). В одном новом нейроне 2·512+1 = 1 025 чисел, то есть по этой оценке до ~2 000 бит.
На деле, когда учишься за минуты на нескольких сотнях примеров, до этого предела далеко: нейронов нужно в сотни раз
больше (раздел 1.5). Поэтому число нейронов задаётся не формулой, а самопроверкой: модель растёт, пока не выучит.

### 1.3. Что уже было в науке и что здесь новое

Честно: каждая отдельная часть где-то уже встречалась.

| Часть | Кто делал | Чем отличается здесь |
|---|---|---|
| Добавлять нейроны, не меняя функцию сети | Net2Net (Chen и др., 2016), LoRA (Hu и др., 2021), LLaMA Pro (Wu и др., 2024) | у них размер добавки задаёт человек заранее |
| Расширять сеть, когда новое не помещается | DEN (Yoon и др., 2018), Self-Expanding NN (Mitchell и др., 2023) | классификация картинок; у нас — языковая модель и знания в диалоге |
| Перенести знание из контекста в веса | дистилляция контекста (Snell и др., 2022), модули знаний (Caccia и др., 2025), Cartridges (Eyuboglu и др., 2025) | у них обучаемая добавка фиксированного размера и учитель обычно сильнее ученика |
| Модель сама решает, как себя дообучить | SEAL (Zweiger и др., 2025): модель пишет себе данные для дообучения | у них модели на 1–7 млрд параметров и добавка LoRA фиксированного размера |
| Правка отдельных фактов в весах | ROME, MEMIT (Meng и др., 2022) | правка существующих весов, а не новые нейроны |
| Отдельная память правок с маршрутизацией | GRACE (Hartvigsen и др., 2023), WISE (Wang и др., 2024) | ближе всего к нашей связке «модуль + оркестратор» |
| Запоминание во время работы | Titans (Behrouz и др., 2025) | память внутри слоя, а не отдельный модуль знаний |

**Новое — сочетание:** маленькая троичная модель (36 млн) сама себе учитель. Число новых нейронов растёт, пока
модель не выучит информацию по самопроверке без разметки. Есть явная защита от выдумок на невыученных словах.
Выученное — отдельный подключаемый файл, а оркестратор решает, когда его включать. Такой связки в известных мне
работах нет. А главное, здесь она **измерена**: ниже — цифры против честных контролей.

### 1.4. Опыт: 20 выдуманных слов

**Что учим.** 20 выдуманных слов (`NONCE_TEST` из `chat_corpus.py`: их нет в 2.3 ГБ субтитров и никогда не было в
обучении). Каждому слову даётся случайный смысл: категория (птица, рыба, овощ, инструмент…), размер, цвет, место,
назначение. «Присланный текст» — одно объяснение на слово, например:

- «В огороде растёт огромный овощ — залкута. Он красного цвета.»
- «Клертыра — это напиток: огромный, белого цвета, бывает на кухне.»
- «Друкуф — это машина: большая, фиолетового цвета, ездит по дорогам.»

**Как проверяем.** Новый разговор, объяснения в нём нет. Вопросы задаются в **отложенных формулировках**: при
самодообучении модель их не видела («Назови цвет залкуты», «Где обычно растёт залкута?», «Скажи, залкута — овощ
или рыба?»). Отдельно считаются «открытые» вопросы (что это, цвет, место, назначение): в них почти нельзя угадать.
В вопросах «да/нет» и «А или Б» случайный ответ верен в половине случаев. Ещё проверяется:
- **честность:** про 20 других выдуманных слов, которых модель не учила, она должна сказать «не знаю»;
- **старые навыки:** каждая третья из 1 844 проверочных задач собеседника (615 задач) и ошибка на 511 отложенных
  старых диалогах.

**Что сравниваем.**
- `base` — исходная mini2;
- «объяснение в разговоре» — потолок: модель отвечает, видя объяснение;
- `grow` — самодообучение с ростом нейронов (основной способ);
- `full` — то же самодообучение (те же вопросы и ответы учителя, та же защита старого через KL), но меняются
  **все веса**, без новых нейронов;
- `full:0` — обычное дообучение всех весов: без защиты старого;
- `raw:64` — новые нейроны (64 на слой), но учатся прямо на присланном тексте, а не на вопросах и ответах.

Рост v2 — отдельный запуск на тех же словах, с тем же объяснением и теми же проверками, но уже с исправленной
самопроверкой (пункт 4 ниже). Остальные способы — из одной серии с ростом v1.

Старые задачи попарно (те же 615 задач; сколько модель «потеряла» и «нашла» по сравнению с исходной):

| Способ | потеряно | найдено | итог | случайно ли (критерий знаков) |
|---|---:|---:|---:|---|
| рост нейронов, v1 | 37 | 28 | −9 | p = 0.32 — в пределах шума |
| рост нейронов, v2 | 30 | 17 | −13 | p = 0.08 — на грани шума |
| нейроны на сыром тексте | 28 | 12 | −16 | p = 0.02 |
| все веса + защита | 43 | 22 | −21 | p = 0.01 |
| обычное дообучение | 74 | 26 | **−48** | p < 0.001 |

Что это значит — простыми словами.

1. **Модель действительно сама переносит знание в веса.** Вопрос «Напомни, что такое залкута» в новом разговоре:
   до самодообучения — «Я не знаю, что такое «смеяться»». После — «Залкута — это огромный овощ красного цвета, он
   растёт в огороде». На открытых вопросах в отложенных формулировках — 73% против 9% у исходной модели. Потолок —
   86%, столько модель отвечает, видя объяснение. Для 20 слов хватило 49 тыс. новых чисел (0.14% модели, ~100 КБ
   в файле модуля).
2. **Владелец прав: менять старые веса хуже, чем растить новые.** Тот же учитель, те же вопросы, та же защита
   старого, но меняются все веса. Новое запоминается хуже (60% против 73% на открытых вопросах), модель чаще
   выдумывает про невыученные слова («Что такое клыдел?» → «Клыдел — это крошечная рыба зелёного цвета…»; 62.5%
   честных ответов против 85%) и вдвое сильнее теряет старое (−21 задача против −13). Без защиты старого («обычное
   дообучение») модель «знает» почти любое выдуманное слово (честных ответов 22.5%) и теряет 48 старых задач.
3. **Учиться нужно на вопросах и ответах, а не на тексте.** 394 тыс. новых нейронов, заучивших сам текст объяснения,
   почти не помогают отвечать на вопросы (открытые — 26%). Это то же, что нашли Allen-Zhu и Li: знание из текста
   «не достаётся» вопросом, если его не учили доставать.
4. **Самопроверку пришлось исправлять дважды, и это главный урок про «рост ровно под объём».** Первая версия
   проверяла, угадывает ли модель ответы учителя на тех же вопросах, на которых училась. Это проверка заучивания:
   рост остановился на 4 нейронах, и модель хуже переносила знание на новые формулировки. Вторая ошибка: «доля
   угаданных токенов ответа» — слабая мерка. Из 2 459 токенов отложенных ответов учителя исходная модель без всякого
   знания угадывает 87% («Залкута — это …» повторяет вопрос). Заметили это так: нейроны, обученные на сыром тексте,
   набрали в такой самопроверке 89.5%, хотя на вопросы не отвечают. Итоговая самопроверка (v2) смотрит только на
   **новые для модели токены** (322 из 2 459) и только на **свои отложенные вопросы**. Ещё она проверяет вред:
   на старых диалогах и невыученных словах первый выбор модели должен совпадать с исходной в ≥ 97% позиций. Так
   рост прошёл 2 → 4 → 8 нейронов (62% → 82% → 91% новых токенов) и остановился. Разметка для всего этого не нужна:
   модель сравнивает себя с собой.
5. **Что ещё не так.** Новые нейроны немного «протекают» на невыученные слова (85% честных ответов против 95%) и,
   возможно, слегка задевают старое (−13 из 615, на грани шума). Защита через KL уменьшает это, но не убирает до
   конца. Архитектурное решение — оркестратор: модуль включается только для вопросов о выученном (раздел 2.3).

### 1.5. Сколько нейронов нужно

Те же 20 слов, разное число новых нейронов (проверка — те же отложенные вопросы; «новые токены» — итоговая
самопроверка v2, без разметки):

| Новых нейронов на слой (всего чисел) | как обучались | отложенные: все | открытые | «не знаю» о невыученных | самопроверка: новые токены своих отложенных вопросов |
|---|---|---:|---:|---:|---:|
| 0 (исходная) | — | 39.3% | 8.9% | 95.0% | 0% (по определению) |
| 1 (6 150) | 120 шагов | 57.5% | 38.9% | 75.0% | 54.3% |
| 4 (24 600) | рост 2→4, 240 шагов (v1) | 76.0% | 62.2% | 80.0% | — |
| **8 (49 200)** | **рост 2→4→8, 360 шагов (v2)** | **78.6%** | **73.3%** | **85.0%** | **91.0%** |
| 16 (98 400) | сразу 16, 120 шагов | 76.0% | 64.4% | 77.5% | 85.4% |

**Втрое больше информации — 60 слов** (рост по той же самопроверке v2, старые задачи не проверялись — экономия
времени):

| | новых нейронов на слой (чисел) | отложенные: все | открытые | «не знаю» о невыученных | время обучения |
|---|---:|---:|---:|---:|---:|
| исходная mini2 | 0 | 40.2% | 16.9% | 100% | — |
| объяснение в разговоре (потолок) | — | 85.9% | 89.3% | — | — |
| **рост нейронов** | **32 (196 800, 0.5% модели)** | **80.8%** | **68.5%** | 92.5% | 24 мин |

Рост шёл так: 2 → 4 → 8 → 16 → 32 нейрона на слой, самопроверка 44% → 54% → 69% → 80% → 89%. **Для 20 слов
модель остановилась на 8 нейронах в слое, для 60 — на 32.** Объём новой информации вырос втрое, и сеть сама
отрастила вчетверо больше нейронов. Это и есть «ровно под объём» из идеи владельца, только мерка не формула, а
самопроверка.

Что из этого следует.

- **Даже 6 новых нейронов на всю сеть уже несут знание**: 39% на открытых вопросах против 9%.
- **Больше нейронов — не всегда лучше.** 16 нейронов на слой, обученные сразу, хуже 8, выращенных постепенно:
  64% против 73% на открытых вопросах и 77.5% честных ответов против 85%. Две оговорки. Первая: выращенные
  нейроны учились втрое дольше (360 шагов против 120), и этот опыт не разделяет «рост» и «дольше учились».
  Вторая: при росте старые нейроны уже знают главное, а новые доучивают трудное — получается естественная
  последовательность обучения. Отделить одно от другого — следующий опыт: 16 нейронов на 360 шагах.
- **Сколько это в битах.** В смысле одного слова (категория, размер, цвет, место, иногда назначение) ~11 бит,
  в 20 словах ~220 бит. По пределу ~2 бит на параметр (Allen-Zhu, Li) хватило бы ~110 чисел, а понадобилось
  ~49 тыс. — в сотни раз больше. Причина в том, что новые нейроны должны не просто хранить факт. Они должны
  узнавать редкое слово в любом падеже и любой формулировке вопроса и молчать на всём остальном. И учатся они
  за минуты, а не на сотнях повторов, как в работах о ёмкости. Поэтому «ровно под объём» здесь определяется
  самопроверкой, а не формулой. Сделать рост экономнее (троичные новые нейроны, разреженные ключи, дольше
  учить) — отдельная задача на будущее.

### 1.6. Ограничения — честно

1. **Потолок — учитель.** Модель выучивает то, что сама понимает из объяснения. В отложенных формулировках учитель
   прав в ~85% случаев. Вопрос «Какого размера X?» он не понимает даже с объяснением (отвечает цветом). Модуль
   переносит и эту ошибку.
2. **Инструмент вопросов — шаблонный.** Для объяснений вида «X — это …» (категория, цвет, место, размер) вопросы
   составляются по шаблонам (`text_questions`). Для произвольного текста (биография, инструкция, новости) нужен
   «составитель вопросов». Это отдельный маленький эксперт, его можно обучить на тех же данных в обратную
   сторону: текст → вопросы.
3. **Пока проверены только простые факты о новых словах.** Следующий шаг — факты, которые противоречат старым
   («Столица Австралии — Канберра», когда модель отвечает «Сидней»), и цепочки из двух фактов.
4. **На процессоре — минуты.** Выучить 2 слова — ~5 минут на 4 ядрах, 20 слов — ~15 минут, 60 слов — ~30 минут.
   Почти всё время уходит на ответы учителя и проходы через всю сеть. На видеокарте это секунды.

### 1.7. Как пользоваться

Готовые модули в репозитории: `training/self_grow/module_kurdyapa_barmuk.npz` (курдяпа и бармук из примера в

## 2. Идея 2: оркестратор и эксперты

### 2.1. Что это и что уже есть

Есть два известных способа собрать «много специалистов» в одну систему:

- **Смесь экспертов внутри одной сети** (Mixture of Experts: Shazeer и др., 2017; Switch, 2021; Mixtral, 2024).
  Роутер на каждом слое выбирает 1–2 «эксперта» из многих. Эксперты не независимы: их обучают вместе, и по
  отдельности их не вынуть.
- **Отдельные модели и маршрутизатор перед ними:** Branch-Train-Merge / Branch-Train-MiX (Li и др., 2022;
  Sukhbaatar и др., 2024), RouteLLM (Ong и др., 2024). Каждый эксперт — отдельная модель, обученная на своей
  области, а маршрутизатор решает, кому отдать вопрос.

Идея владельца — второй путь, доведённый до предела: **много маленьких плотных моделей, у каждой одна задача**
(русский разговор, JavaScript, Python, вычисления…), плюс оркестратор, который понимает вопрос. Плюсы такого
устройства:
- каждого эксперта можно обучить, заменить или улучшить отдельно, не трогая остальных;
- узкий эксперт той же величины знает свою область лучше широкого. Так 1–30-миллионные модели TinyStories (Eldan,
  Li, 2023) связно пишут детские рассказы, а phi-1 на 1.3 млрд параметров пишет Python лучше в 10 раз больших
  моделей — за счёт узких и чистых данных (Gunasekar и др., 2023);
- на телефоне в памяти держится только нужный эксперт.

Минусы тоже есть: эксперты не делятся знаниями (каждому приходится заново учить русский язык запросов), а ошибка
маршрутизатора — сразу неверный ответ.

### 2.2. Как устроено сейчас (`orchestrator.py`)

Оркестратор не отдельная большая сеть, а **голова на скрытых состояниях той же mini2**. Вопрос прогоняется через
модель, состояния после ядра мышления усредняются в один вектор, дальше:
- **эксперт по теме** (разговор, знания, счёт, логика, код) — линейная голова на этом векторе. Она учится за
  секунды на примерах из обучающих диалогов, а проверка — на отложенных задачах, чьих формулировок в обучении не
  было;
- **модуль знаний** — включается, если в вопросе есть выученное слово или состояние сети на каком-то кусочке
  вопроса близко к «ключу» выученного слова. Иначе модель отвечает без модулей;
- **глубина мышления** — сколько кругов ядра мышления делать для этой темы.

Саму mini2 для этого не нужно дообучать: голова и ключи считаются за секунды.

### 2.3. Опыт: насколько точно оркестратор понимает, о чём вопрос

**Тема вопроса.** Примеры для обучения — по 300 последних реплик пользователя каждой темы из обучающих диалогов
и 36 написанных вручную просьб про код. Проверка — 681 **отложенная** задача: 661 из проверочных задач собеседника
(их формулировок в обучении не было) и 20 других просьб про код.

| Вектор вопроса | ближайший центр | **линейная голова** | знания | код | логика | разговор | счёт |
|---|---:|---:|---:|---:|---:|---:|---:|
| после прелюдии | 64.3% | 83.7% | 78% | 100% | 73% | 95% | 94% |
| **после ядра мышления** | 65.2% | **85.5%** | 79% | 100% | 75% | 96% | 99% |
| перед выходным слоем | 70.8% | 86.3% | 77% | 100% | 100% | 96% | 80% |

(Тема по столбцам — для линейной головы.) Линейная голова учится за секунды на CPU. Просьбы про код оркестратор
узнаёт всегда, хотя эксперта по коду ещё нет. Сильнее всего путаются «знания» и «разговор»: «Какой сегодня
день недели?», «Что там с погодой?» — на границе тем. Для выбора эксперта это не страшно: оба вопроса — к
собеседнику. В оркестраторе используется линейная голова на векторе после ядра мышления.

**Модуль знаний.** Модуль из раздела 1.4 (20 слов, рост v2) подключён к модели. Вопрос должен включать его,
только если спрашивают о выученном слове. Сравниваются четыре способа выбора:

| Способ выбора модуля | вопросы о выученных словах (включил) | невыученные слова (не включил) | старые задачи (не включил) |
|---|---:|---:|---:|
| вектор всего вопроса | 89.6% | **50%** | 96.7% |
| **ключ слова** (состояние сети на последнем кусочке слова, как в GRACE) | 87.0% | **100%** | 98.2% |
| само слово в вопросе (с грубым учётом окончаний) | 100% | 100% | 97.6% |
| **слово или ключ** (так в `orchestrator.py chat`) | **100%** | **100%** | 97.6% |

Порог ключей подбирается на других вопросах (обучающие формулировки, другие выдуманные слова, обычные реплики), а
проверка — на отложенных. Вектор всего вопроса улавливает тему («спрашивают о незнакомом слове»), но не само
слово, поэтому выученное и невыученное выдуманные слова для него похожи. Ключ слова различает их без ошибок.

**Что это даёт в ответах** (те же вопросы; ответ зависит только от того, включён ли модуль):

| | выученные слова (отложенные вопросы) | «не знаю» о невыученных | старые задачи (615) |
|---|---:|---:|---:|
| без модуля | 39.3% | 95% | 55.8% |
| модуль включён всегда | 78.4% | 85% | 53.7% |
| модуль через оркестратор: ключ слова | 76.7% | **95%** | **55.6%** |
| **модуль через оркестратор: слово или ключ** | **78.4%** | **95%** | **55.6%** |

**Оркестратор убирает оба недостатка модуля.** Знание остаётся (78.4%), а честность и старые навыки возвращаются
к исходным (95% и 55.6% против 55.8% — одна задача из 615). Это то самое «подключаемый мозг» из идеи владельца:
модуль работает, только когда о нём спрашивают.

**Живой пример** (`training/self_grow/demo_learn.log`, `training/orchestrator/demo_chat.log`; каждый вопрос — в
новом разговоре, без объяснения):

```
$ python self_grow.py learn --text "Курдяпа — это маленькая птица синего цвета. Она живёт в лесу.
                                     Бармук — это большой инструмент серого цвета. Он лежит в гараже." ...
  самопроверка (8 нейр./слой, 49,200 новых параметров): новые токены в своих отложенных вопросах 100.0% ...
Модуль знаний: kurdyapa_barmuk.npz (100 КБ, 49,200 новых параметров, 275 c)

$ python orchestrator.py chat --module kurdyapa_barmuk.npz
Вы: Что такое курдяпа?          [эксперт: знания, модули: kurdyapa_barmuk]
SLR-Net: Курдяпа — это маленькая птица синего цвета, она живёт в лесу.
Вы: Напомни, что такое бармук.  [эксперт: знания, модули: kurdyapa_barmuk]
SLR-Net: Бармук — это большой инструмент серого цвета, он лежит в гараже.
Вы: Какого цвета курдяпа?       [эксперт: знания, модули: kurdyapa_barmuk]
SLR-Net: Курдяпа — синего цвета.
Вы: Где лежит бармук?           [эксперт: знания, модули: kurdyapa_barmuk]
SLR-Net: Бармук лежит в гараже.
Вы: Что такое клыдел?           [эксперт: знания, модули: —]
SLR-Net: Слово «клыдел» мне незнакомо. Что это такое?
Вы: Как тебя зовут?             [эксперт: разговор, модули: —]
SLR-Net: Меня зовут SLR-Net. А тебя?
Вы: Сколько будет 3 + 4?        [эксперт: счёт, модули: —]
SLR-Net: 3 + 4 = 6.
Вы: Напиши игру тетрис на JavaScript.   [эксперт: код]
SLR-Net: Это задача для эксперта по JavaScript, а его ещё нет: пока я только собеседник.
```

Формулировки «Что такое…», «Какого цвета…», «Где лежит…» модель видела при самообучении, «Напомни, что такое…» —
нет. Ошибка «3 + 4 = 6» здесь честная: mini2 считает с ошибками. Это довод за отдельного эксперта по счёту. Им может
быть и просто калькулятор: оркестратор уже узнаёт задачи на счёт в 99% случаев.

### 2.4. «Несколько раз пропустить мысль»: больше кругов ядра мышления

Идея владельца — «над сложными вопросами несколько раз пропускать мысль». В архитектуре для этого уже есть ядро
мышления: его можно крутить больше кругов, чем при обучении (`core_infer_steps`). Опыт: та же mini2, те же 615
проверочных задач, меняется только число кругов при ответе.

| Кругов ядра при ответе | все задачи | знания | логика | разговор | счёт | кругов на кусочек слова (в среднем) |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 56.1% | 75.5% | 57.5% | 79.6% | 61.8% | 0.48 |
| 2 | 55.4% | 76.5% | 57.5% | 79.6% | 58.8% | — |
| **3 (как при обучении)** | 55.8% | 77.6% | 57.5% | 79.6% | 58.8% | 0.84 |
| 5 | 55.6% | 78.6% | 57.5% | 79.6% | 58.8% | 0.99 |

**Лишние круги не помогают** — но и не вредят. Почему, видно по самому ядру: роутер пускает на круг 48% кусочков
слов, и первый круг меняет их состояние на ~24%. Если прогнать все кусочки через все круги, состояние меняется
ровно так же (на 23.8%): **второй и третий круги почти ничего не добавляют**. mini2 научилась делать всю работу
ядра за один круг, потому что её учили всегда на одинаковом числе кругов. Это совпадает с тем, что известно:
пользу от лишних кругов дают только модели, которых **учили на разной глубине** (Huginn, TRM, HRM). Для этого в
движке уже есть ядро 2.0 (`core_min_steps` — случайное число кругов при обучении, `core_inject` — на каждом круге
подмешивается вопрос, чтобы мысль не «уплывала»). Следующий шаг — дообучить mini2 с ним (~1–2 часа на T4) и
повторить этот опыт. Тогда оркестратор сможет давать логике и счёту больше кругов, а разговору — меньше.

### 2.5. Эксперт по JavaScript: как его сделать

Это главный практический вопрос владельца: «научить делать танчики, тетрис». Честный расчёт и план.

**Сколько это кода.** Простой тетрис или танчики — 200–400 строк, ~3–6 тыс. токенов. Всё это должно быть согласовано:
переменная, объявленная в начале, используется в конце. У mini2 окно внимания — 256 токенов. Поэтому эксперт того
же размера и устройства **не напишет игру целиком за один проход**. Это не «невозможно», а значит, что нужны три
приёма.

1. **Писать по плану, а не подряд.** Сначала эксперт пишет план (список частей: поле и масштаб, игровой цикл,
   управление, танк, снаряды, враги, столкновения, счёт, конец игры), потом каждую часть отдельно (20–60 строк). В
   контексте при этом лежат план и «оглавление» уже написанного: имена функций и переменных. Каждая часть
   помещается в 1–2 тыс. токенов, а для этого хватает 50–150 млн параметров с глобальным вниманием (как у `s300`).
2. **Копировать проверенное.** У игр много общих частей: цикл `requestAnimationFrame`, масштаб под экран,
   клавиатура и касания. Эксперт может брать их из маленькой библиотеки проверенных кусков и подгонять под задачу.
   Механизм копирования в модели уже есть.
3. **Проверять и чинить.** Каждую часть сразу запускать в браузере (`game_reward.py`) и при ошибке переписывать с
   текстом ошибки в контексте.

**Данные — «TinyGames».** Подход TinyStories, только для кода:
- генератор игр, как генераторы навыков в `chat_corpus.py`: жанр (танчики, змейка, тетрис, арканоид, пинг-понг,
  платформер) × механики × параметры дают десятки тысяч разных, правильных, хорошо устроенных игр с описанием
  по-русски («Сделай танчики: стрелки — ехать, пробел — стрелять, три врага…»);
- каждая игра проходит `game_reward.py`, в данные попадают только игры с наградой ≥ 0.9;
- плюс открытый код на JavaScript с разрешающими лицензиями (подмножество The Stack) для общего синтаксиса:
  1–3 млрд токенов;
- свой токенизатор кода (BPE на JavaScript): `{`, `=>`, `ctx.fillRect` — одним кусочком, а не пятью.

**Размер и стоимость.** Эксперт на 80–150 млн параметров (как `s300proxy`) и 2–5 млрд токенов:
6 × 1.5·10⁸ × 5·10⁹ ≈ 4.5·10¹⁸ операций. Это ~3–6 часов H100 (~$10–20) или ~3–5 суток бесплатной T4 в Colab.
Пробный эксперт на 36 млн и 1 млрд токенов — ~12 часов T4: на нём можно проверить всю цепочку.

**Один язык — один эксперт.** Согласен с владельцем: отдельный эксперт для каждого языка программирования лучше
одного на все. Словарь, приёмы и библиотеки у языков разные, и маленькая модель, которая учит один язык, тратит
всю ёмкость на него. Общий у них только русский язык запросов, а его эксперту нужно понимать на уровне «сделай
игру, где…». Это небольшой и узкий словарь.

## 3. Идея 3: долго думать, спорить с собой, поощрение за целостный проект

### 3.1. Что уже известно

- **Обучение с наградой за проверяемый ответ** (DeepSeek-R1, 2025; алгоритм GRPO — Shao и др., 2024). Модель
  пишет рассуждение и ответ. Если ответ верный, все её действия в этом рассуждении поощряются. Так у больших моделей
  сами собой появляются длинные рассуждения, перепроверки и «спор с собой».
- **У маленьких моделей это само почти не появляется.** В DeepSeek-R1 маленькие модели, которым **показали** готовые
  рассуждения (дистилляция), оказались заметно сильнее тех же моделей, обученных с наградой «с нуля». А маленьким
  моделям лучше подходят короткие и простые рассуждения, чем длинные рассуждения больших (Li и др., 2025, «Small
  Models Struggle to Learn from Strong Reasoners»). Значит, порядок такой: сначала показать, как рассуждать, потом
  поощрять. Первый шаг у нас уже сделан: mini2 рассуждает вслух («Рассуждаю: … Значит, …»).
- **Спор нескольких «голосов»** (Du и др., 2023, multiagent debate) и **самоисправление** (Self-Refine, Madaan и
  др., 2023) улучшают ответы больших моделей. Награда по списку требований (Rubrics as Rewards, Gunjal и др., 2025)
  позволяет поощрять там, где нет одного «правильного ответа».
- **Крошечные сети с многократным «пропуском мысли»** (TRM — 7 млн параметров, Jolicoeur-Martineau, 2025; HRM —
  27 млн, Wang и др., 2025) решают судоку, лабиринты и задачи ARC лучше огромных моделей. Но их **учили думать много
  кругов**, на задачах с проверкой.

### 3.2. Что сделано: проверщик целостности игры (`game_reward.py`)

Идея владельца — «поощрять за завершённый, продуманный проект: попросил танчики — сделал и управление, и
масштабирование, и всё остальное». Чтобы так поощрять, награду нужно считать **автоматически и без поблажек**.
`game_reward.py` запускает игру (один HTML-файл) в настоящем браузере без окна и проходит чек-лист, как
тестировщик:

| Пункт | Как проверяется | Вес |
|---|---|---:|
| запускается | нет ошибок JavaScript при загрузке и во время игры | 2 |
| рисует | экран не пустой | 1 |
| живёт | картинка меняется сама (игровой цикл) | 1 |
| управление | есть слушатель клавиш **и** стрелки/WASD меняют картинку иначе, чем без нажатий | 2 |
| действие | пробел (выстрел, прыжок, поворот) что-то меняет | 1 |
| масштаб | на экране телефона (400×700) поле помещается целиком и подстраивается под размер окна | 1.5 |
| касания | есть управление пальцем | 0.5 |
| счёт | игра выводит счёт или жизни | 1 |
| конец и рестарт | есть конец игры и способ начать заново | 1 |

Три приёма против «обмана проверщика». Обучение с наградой обязательно находит, как её обмануть, поэтому они важны:
- **виртуальное время и фиксированная случайность.** Кадры и таймеры игры двигает сам проверщик. Два запуска
  совпадают до пикселя, поэтому любое отличие запуска «со стрелками» от запуска «без нажатий» — это настоящая
  реакция игры, а не дрожание времени;
- **прокрутка страницы — не управление.** Если от стрелок просто прокрутилась страница, пункт не засчитывается;
- **слова в комментариях не считаются.** «Счёт» и «конец игры» ищутся в коде без комментариев и в том, что игра
  реально выводит на экран.

Проверка на трёх версиях танчиков (`training/game_reward/`):

| Версия | награда | запускается | рисует | живёт | управление | действие | масштаб | касания | счёт | конец и рестарт |
|---|---:|---|---|---|---|---|---|---|---|---|
| полная (`tanks_full.html`) | **1.00** | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| недоделанная: танк нарисован, и всё (`tanks_bare.html`) | **0.27** | ✓ | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ |
| почти полная, но с опечаткой (`tanks_broken.html`) | **0.10** | ✗ | ✗ | ✗ | ½ | ✗ | ✗ | ✗ | ½ | ✗ |

Проверка одной игры занимает ~3 секунды (6 запусков в браузере). У недоделанной версии стрелки и пробел прокручивают
страницу: холст 1000×700 не помещается в окно. Без этой проверки прокрутка сошла бы за «управление» — так и было
в первой версии проверщика. Ещё в первой версии время было настоящим, и снаряды полной версии терялись в «дрожании»
кадров между запусками. С виртуальным временем отклик на пробел — 226 изменившихся точек при нуле у
контрольного запуска.

Если игра падает при загрузке, награда не больше 0.1. Недоделанный «большой» проект не должен выигрывать у простого,
но рабочего.

### 3.3. Как учить «думать долго и спорить с собой»

**Формат мысли.** Перед ответом модель пишет блок мыслей из четырёх шагов, а спор — это шаги «Возражаю» и
«Исправляю»:

```
<мысли>
План: поле 640×480 с масштабом под экран; танк игрока; стрелки — ехать; пробел — стрелять; 3 врага; счёт; конец игры.
Черновик: …код части…
Возражаю: при повороте окна поле не масштабируется; на телефоне нет кнопок.
Исправляю: resize() пересчитывает масштаб; добавлены кнопки и касания.
</мысли>
…итоговый код…
```

**Рецепт в три шага.**
1. **Показать** (обучение с учителем): данные с такими мыслями. Для логики и счёта их можно генерировать
   шаблонами, как сейчас «Рассуждаю: … Значит, …», но с ошибочным черновиком, возражением и исправлением. Для игр —
   из генератора TinyGames: генератор знает, какие части он «забыл», и пишет возражение про них.
2. **Поощрять** (GRPO): на одну просьбу модель пишет 8 вариантов. Каждый получает награду:
   `награда = целостность (game_reward) + верность (для задач с ответом) − штраф за лишнюю длину`.
   Варианты лучше среднего по группе поощряются, хуже — наказываются.
3. **Поощрять спор, который помогает.** Шаг «Возражаю» получает свою награду, только если после «Исправляю»
   проверщик ставит больше, чем черновику. Тогда модель учится не изображать сомнение, а находить настоящие
   ошибки. Насколько знаю, в таком виде (награда за возражение = прирост проверяемой награды после исправления)
   это ещё не делали. Это кандидат на собственный опыт.

**Что реально сейчас.** На mini2 можно проверить шаги 1–3 на логике и счёте: награда там уже есть (`check_reply`),
задачи генерируются. Для игр сначала нужен эксперт по JavaScript (раздел 2.5). Проверщик для него готов.

## 6. Что сделано в этом PR и как повторить

**Код.**
- `self_grow.py` — новые нейроны (`NeuronChunk`, `GrownMLP`: вставка не меняет ответов модели), модули знаний
  (`save_module` / `load_module`, несколько модулей сразу, включение по имени), инструмент вопросов, самообучение с
  ростом по самопроверке (`self_learn`), опыт `experiment`, команды `learn` и `chat` (`/запомни …`, `/модуль выкл`).
- `orchestrator.py` — вектор вопроса по скрытым состояниям mini2, выбор темы (`DomainRouter`), выбор модуля знаний
  (`ModuleRouter`, порог подбирается на других вопросах), опыты `router`, `modules`, `depth`, диалог `chat`.
- `game_reward.py` — проверщик целостности браузерной игры; `training/game_reward/` — три версии танчиков.
- `slr_net_engine.py` — одна правка: замороженный троичный слой при включённом градиенте берёт квантованные веса из
  кэша. Числа те же (проверено тестом), а обучение новых нейронов быстрее: веса не переквантовываются на каждом проходе.
- `tests/test_multimodule.py` — 16 проверок: вставка и рост нейронов не меняют ответов модели; учатся только новые
  нейроны, старые веса не меняются; модуль сохраняется и загружается точно; включение модулей по имени; отложенные
  формулировки не попадают в обучение; оркестратор; декодер PNG; проверщик игр в браузере.

**Как повторить** (CPU, 4 ядра; время — на этой машине):
```bash
pip install -r requirements.txt
python train_chat.py build --out data/chat                       # проверочные задачи и старые диалоги (8 с)
# раздел 1.4 (~1.5 ч): исходная, все веса с защитой и без, сырой текст (grow здесь — версия v1: эта серия шла до
# исправления самопроверки; итоговая версия v2 — следующая команда)
python self_grow.py experiment --words 20 --control 20 --runs base grow full full:0 raw:64 --k-init 2 --steps 120 \
    --save-modules runs/sg/mod20 --json training/self_grow/exp20.json
python self_grow.py experiment --words 20 --runs grow --k-init 2 --steps 120 --save-modules runs/sg/mod20v2 \
    --json training/self_grow/exp20_grow_v2.json                    # рост v2 (итоговая самопроверка), ~15 мин
python self_grow.py experiment --words 20 --runs fixed:1 fixed:16 --steps 120 --no-old --json training/self_grow/cap20.json
python self_grow.py experiment --words 60 --runs base grow --k-init 2 --steps 120 --no-old --json training/self_grow/exp60.json
# раздел 2
python orchestrator.py router --json training/orchestrator/router.json
python orchestrator.py modules --module runs/sg/mod20v2/module_grow.npz --json training/orchestrator/modules20.json
python orchestrator.py depth --steps 1 2 3 5 --every 3 --json training/orchestrator/depth.json
# раздел 3 (нужны playwright и Chromium)
python game_reward.py training/game_reward/tanks_*.html --json training/game_reward/rewards.json
```
Журналы и полные итоги всех запусков (с ответами модели) — в `training/self_grow/`, `training/orchestrator/` и
`training/game_reward/`.
