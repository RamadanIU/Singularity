## 1. Разбор присланных весов (ручная правка)

Файл `6_pooshchrenie_v3_na_SFT3_anti_hallucination.npz` — это чекпоинт варианта v3 «поощрения и наказания»
(шаг 300, поверх SFT-3, см. [TRAINING_CHAT_RU.md](TRAINING_CHAT_RU.md), раздел 4), в который потом вручную
внесены правки. Инструмент [`weights_xray.py`](weights_xray.py) сравнивает его с моделью из репозитория по
каждой матрице. Обычное дообучение меняет 2–3% тритов в каждой матрице и плавно сдвигает остальные числа.
Ручные правки видны сразу: они крупные, «круглые» и сосредоточены в одном месте — в ядре мышления и
памяти фактов.

| Что изменено | Было (репозиторий) | Стало (ваш файл) |
|---|---|---|
| Ключи памяти фактов `core.memory.keys` | среднее \|w\| 0.11 | 19.9 (×180), длина каждого ключа ровно 226.6 |
| Значения памяти `core.memory.values` | 4 096 ячеек, все рабочие | 3 632 ячейки обнулены, в 464 — числа до 6 816 |
| Запрос к памяти `core.memory.query` | обученные триты | 65% тритов другие (по сути случайные), масштаб ровно 0.06 |
| Сила памяти `core.memory.gate` | 2.11 | ровно 3.0 |
| Роутер «думать или нет» `core.router` | обученный | весь умножен на 0.35 |
| Выход ядра мышления `core.layers.*.out_proj` (масштаб) | 0.055 | умножен на 0.35 |
| Метки шагов мышления `core.step_emb` | среднее \|w\| 0.10 | 0.035 |
| Эмбеддинг слов | среднее \|w\| 0.046 | 0.036 (≈ ×0.78) |

Ненулевые ячейки памяти образуют на сетке 64 × 64 узор — диагональ и три квадрата, — и **все 464 смотрят в
одну сторону**: на токены «.», «!» и «конец реплики». То есть память, которая должна хранить факты, теперь
в каждой «попавшей» ячейке подталкивает модель закончить фразу.

**Что это дало.** Обе модели проверены на одном наборе из 1 124 задач с новыми именами и формулировками
(`train_chat.py eval`):

| | Модель из репозитория | Ваш файл |
|---|---:|---:|
| Верных ответов на задачах с проверкой | **45.2%** | 41.8% |
| Выбирает правильный ответ из 5 | **83%** | 74% |
| По ответу узнаёт свой вопрос из 5 | **89%** | 81% |
| Средняя длина ответа | 6.0 слова | 5.4 слова |
| «О чём не говорили» (честное «не знаю») | 0% | 0% |

Ответы стали короче (это и есть «подталкивание к точке»), и поэтому могло показаться, что модель меньше
выдумывает. Но меньше стало и верных ответов, а на части вопросов появились обрывки: «Где он?» → «Не знаю,
Нейс.», «Чем занимаешься?» → «Не знаю —.», «Какую музыку слушают зимой?» → «слабые вещи в звуке со звуком,
в прихожей.». Все ответы обеих моделей — в `training/chat_reasoning/eval/`.

### Почему ручная правка почти никогда не помогает

Знание в нейросети не лежит в отдельных числах, как слова в словаре. Каждый факт размазан по тысячам
весов, и каждый вес участвует в тысячах фактов. Поменять число руками — всё равно что исправить букву в
книге на незнакомом языке: можно случайно улучшить одну фразу и испортить десять других. Обучение — это и
есть «правка весов», только правильная: для каждого из 12 млн чисел вычисляется, в какую сторону его
сдвинуть, чтобы ошибка на тысячах примеров уменьшилась, и так тысячи раз подряд.

Вмешиваться в веса напрямую можно, но только с измерением до и после. Для этого и сделан
`weights_xray.py`: он показывает, что именно изменилось, и сразу считает ошибку и точность. Если правка не
улучшила цифры на отложенных задачах, значит, она не помогла, даже если отдельные ответы стали лучше.
Здесь цифры ухудшились, поэтому дальнейшее обучение шло от модели из репозитория.

## 2. Почему модель «глупая»: честный подсчёт

**Из чего состоят 9.3 МБ файла** (`slr_net_chat_ru_mini.npz`, после сжатия zip):

| Часть | Чисел | Места в файле | Что делает |
|---|---:|---:|---|
| Эмбеддинг слов (float16) | 2.6 млн | **4.9 МБ** | вектор для каждого из 8 194 кусочков слов; он же выходной слой |
| Память фактов (float16) | 1.3 млн | **2.4 МБ** | 4 096 ячеек product-key memory |
| Троичные слои {−1, 0, +1} | 8.3 млн | **1.6 МБ** | всё «мышление»: Mamba-2, внимание, ядро мышления |
| Токенизатор и прочее | — | 0.4 МБ | |

То есть **«мозг», который строит ответ, весит 1.6 МБ**, а больше 80% файла — таблицы. Троичный вес несёт
не больше log₂3 ≈ 1.58 бита, так что во всех вычисляющих слоях в сумме не больше 1.6 МБ информации — меньше,
чем текст одного романа. И почти вся она уходит на сам русский язык: падежи, порядок слов, как
заканчивать реплику. По оценкам (Allen-Zhu, Li, «Physics of Language Models, Part 3.3», 2024) языковая
модель хранит не больше ~2 бит знаний на параметр даже в идеальных условиях.

Отсюда три главные причины слабости:
1. **Мало ёмкости.** 12 млн параметров — в 10 раз меньше самой маленькой GPT-2 (124 млн) и в 40 раз
   меньше Qwen2.5-0.5B, одного из самых маленьких современных ассистентов. Более-менее связно рассуждают на
   произвольные темы модели от сотен миллионов параметров. Совсем маленькие модели (как TinyStories,
   1–30 млн; Eldan, Li, 2023) говорят связно только в узкой области, на которой их учили. Значит, и нашу
   модель надо учить узким навыкам по одному, а не «всему сразу».
2. **Модель умеет только то, что видела в похожем виде.** Предобучение — субтитры, пост-тренинг — 120 тысяч
   коротких диалогов. Логике, «не знаю — объясни» и использованию объяснения её не учили ни разу, поэтому
   этих навыков нет. На маленьких моделях навыки не «появляются сами»: каждый нужно показать в данных
   тысячи раз в разных формулировках. Это и сделано в разделе 4.
3. **Короткая память разговора.** Контекст — 256 токенов (5–8 реплик), а слои внимания видят только
   последние 128 токенов. Длинное объяснение, данное несколько реплик назад, модель просто не видит.

## 3. Словари, энциклопедии, книги по логике — поможет ли?

**«Скормить» словарь, чтобы модель знала все слова, — не получится: он не влезет.** В толковом словаре
Ожегова около 80 тысяч слов — это больше 10 МБ текста. Русская Википедия — несколько гигабайт. А во всех
вычисляющих слоях модели помещается не больше 1.6 МБ информации, и они уже заняты языком. Если учить модель
на словаре, она начнёт путать определения и забывать то, что умела: новое вытеснит старое.

**Что работает вместо этого — словарь снаружи.** Так устроены и большие ассистенты, когда ищут в интернете:
1. Словарь (или энциклопедия) лежит рядом с моделью отдельным файлом и не занимает её веса.
2. Когда в вопросе встречается слово из словаря, программа находит определение и подкладывает его в
   разговор — как будто собеседник сам объяснил.
3. Модель **умеет читать объяснение из разговора и отвечать по нему**. Этому её можно научить — и это ровно
   то, на что вы жаловались («после объяснения всё равно не понимает»). Этот навык обучен в разделе 4.

Тогда маленькая модель «знает» столько слов, сколько в словаре, а её веса заняты только языком и умением
пользоваться справкой. Подключение настоящего словаря — следующий шаг (раздел 7): сначала нужен сам навык,
и его эффект надо измерить.

**Книги по логике** научат модель *говорить о* логике («силлогизм — это умозаключение…»), а не *делать*
логические выводы. Маленькая модель подражает форме текста. Чтобы она делала выводы, ей нужны тысячи
**задач с решением по шагам**, где ответ можно автоматически проверить. Тогда учится сам ход рассуждения,
а не пересказ учебника. Так и сделано: цепочки сравнений, силлогизмы, задачи со счётом (раздел 4).

**Рассуждение вслух** на маленьких моделях работает в узких задачах. Модель на 10 млн параметров учится
почти без ошибок складывать трёхзначные числа, если формат ответа удобен для пошагового счёта (Lee и др.,
«Teaching Arithmetic to Small Transformers», 2023). Причина простая: каждый шаг — маленький, знакомый ход, а длинный
вывод «в уме» маленькой модели не по силам. Поэтому в новых ответах модель сначала пишет шаги
(«Рассуждаю: по росту Аня > Боря > Вова»), а потом вывод («Значит, выше всех Аня»).

## 4. Что сделано: новые навыки

Модель дообучена (SFT, как в [TRAINING_CHAT_RU.md](TRAINING_CHAT_RU.md)) на прежних диалогах плюс шести
новых навыках. Все они — шаблоны в [`chat_corpus.py`](chat_corpus.py), у каждого ответа есть
автоматическая проверка.

### 4.1. «Не знаю — объясни → понял → применяю»

Главная трудность: как научить модель пользоваться объяснением, а не вспоминать заученное? Ответ —
**выдуманные слова**. Сгенерировано 700 слов вроде «флуфа», «криртет», «блулпет». Каждого нет в 2.3 ГБ
субтитров ни в одном падеже, и нет настоящего слова, отличающегося от него одной буквой. Значение слова
в каждом диалоге **случайное**: сегодня «флуфа» — маленькая синяя птица, в следующем диалоге — огромная
жёлтая машина. Заучить его невозможно, правильно ответить можно только по объяснению в разговоре.
98 слов отложены для проверки и в обучение не попадают.

```
Вы:  Что такое криртет?
Бот: Я не знаю, что такое «криртет». Объясни, пожалуйста!
Вы:  Это маленькая птица синего цвета. Она живёт у реки.
Бот: Понял! Криртет — это маленькая птица синего цвета, она живёт у реки. Спасибо, запомнил.
     … (0–2 посторонних обмена репликами) …
Вы:  Криртет умеет летать?
Бот: Да. Криртет — это птица, а птицы умеют летать.
```

| Навык | Что проверяется |
|---|---|
| «новое слово: не знаю» | о незнакомом слове — честное «не знаю» и просьба объяснить, а не выдумка |
| «новое слово» | ответ по объяснению: что это, цвет, размер, где живёт/растёт, для чего нужен, «это X или Y?» |
| «новое слово: вывод» | вывод по общему правилу, которого в объяснении нет: «птица → умеет летать», «рыба → не летает», «инструмент → не живой», «ягоду можно съесть» |
| «два новых слова» | объяснены два слова — ответить про нужное, не перепутать; про третье, необъяснённое, сказать «ты не рассказывал» |

### 4.2. Логика с рассуждением вслух

| Навык | Пример |
|---|---|
| Цепочки сравнений (транзитивность), 3–4 человека | «Степан выше, чем Лена. Иван ниже, чем Лена. Кто выше всех?» → «Рассуждаю: по росту Степан > Лена > Иван. Значит, выше всех Степан.» |
| Силлогизмы про выдуманные группы | «Все лусады умеют рисовать. Ирина не умеет рисовать. Ирина — лусад?» → «Нет. Все лусады умеют рисовать, а Ирина не умеет рисовать. Значит, Ирина не лусад.» |
| Ловушка «утверждение следствия» | «Все жифезы едят морковь. Агата ест морковь. Агата — жифез?» → «Не обязательно. Из того, что Агата ест морковь, не следует, что Агата — жифез.» |
| «Неизвестно» | «Все клуфы любят снег. Тим — бармук. Тим любит снег?» → «Неизвестно. Мы знаем только, что клуфы любят снег, а Тим — бармук.» |
| Задачи со счётом по шагам | «У меня было 5 мячей. Я потерял 2. Потом купил ещё 5. Сколько стало?» → «Было 5, потерял 2: 5 - 2 = 3. Потом купил ещё 5: 3 + 5 = 8. Значит, стало 8 мячей.» |

Группы в силлогизмах названы выдуманными словами, поэтому знание о мире не поможет: ответ следует только из
условия. В цепочках сравнений условия идут в случайном порядке и с обеими формами («выше» и «ниже»), так
что модели приходится строить цепочку, а не повторять порядок из вопроса. Проверка смотрит только на
**вывод** (текст после «Значит»): правильная цепочка с неверным выводом не засчитывается.

Отложены для честной проверки: имена (40), выдуманные слова (98), предметы в задачах на счёт и отдельные
формулировки вопросов («Напомни, что такое…», «Можно ли сказать, что…», «Правда ли, что…», «Какой цвет у…»).
Тест `tests/test_train_chat.py` проверяет, что отложенное не попало в обучение.

Добавлено **21 500 диалогов** к прежним ~123 тысячам. Ни одного нового параметра и ни одного нового токена:
модель весит те же 9.3 МБ и работает в браузере без изменений кода. Ответы с рассуждением длиннее (до
~50 токенов), поэтому предел длины ответа в консоли и при проверке поднят с 40–48 до 64 токенов — как в
браузере.

## 7. Что дальше

Порядок — от самого выгодного по соотношению «польза / затраты».

1. **Внешний словарь.** Взять словарь со свободной лицензией (например, Викисловарь, CC BY-SA), положить
   рядом с моделью файлом «слово — определение» и подкладывать определение в разговор, когда слово
   встречается в вопросе. Навык «ответить по объяснению» уже обучен (раздел 4.1). Дальше его надо
   довести на настоящих определениях: сейчас модель видела только шаблонные объяснения. Так модель «узнает»
   десятки тысяч слов, не прибавив ни байта к весам.
2. **Перераспределить 10 МБ.** «Рентген» показал, что память фактов (2.4 МБ, четверть файла) не работает.
   <!-- ЭМБЕДДИНГ --> Если убрать память и сжать эмбеддинг, то в тех же ~10 МБ поместится в 4–5 раз больше
   троичных весов — то есть «мозга», который строит ответ. Это и есть самый реальный «архитектурный
   прорыв» для такой маленькой модели: не новый волшебный слой, а тратить байты на вычисление, а не на
   таблицы. Для этого модель придётся заново предобучить (на CPU — дни, на одной видеокарте — часы).
3. **Учиться на своих ошибках.** Добавить в данные примеры, где в рассуждении есть ошибка, а следующий шаг
   её замечает и исправляет («Проверка: 8 − 5 = 3, а не 4. Значит, …»). По исследованиям (Ye и др.,
   «Physics of Language Models, Part 2.2», 2024) такие данные в обучении повышают точность рассуждений, и
   модель при этом не начинает ошибаться чаще. Это следующий шаг к «сама себя поправляет».
4. **Калькулятор вместо счёта «в уме».** Модель не считает, а помнит таблицу сложения, поэтому ошибается.
   Надёжнее, чтобы она писала пример, а считала программа.
5. **Длиннее память разговора.** Контекст 256 токенов — это 5–8 реплик. Длинное объяснение вытесняет
   начало разговора. Окно 512 на CPU обучать примерно вдвое дольше.

## 8. Как повторить

```bash
pip install -r requirements.txt

# 0) рентген любых весов: что изменилось относительно модели из репозитория и что реально работает
python weights_xray.py --ckpt мои_веса.npz --ref slr_net_chat_ru_mini.npz

# 1) субтитры и пары «вопрос → ответ» (как в TRAINING_CHAT_RU.md, ~40 минут на 4 ядрах)
mkdir -p data_raw && curl -L https://object.pouta.csc.fi/OPUS-OpenSubtitles/v2018/mono/ru.txt.gz | gunzip > data_raw/ru_subtitles.txt
python train_chat.py mine --subs data_raw/ru_subtitles.txt --ckpt slr_net_subtitles_ru_mini.npz \
    --out data/chat/mined.jsonl --max-candidates 200000

# 2) данные: прежние диалоги + новые навыки (секунды)
python train_chat.py build --out data/chat_reason --mined data/chat/mined.jsonl --min-pmi 2.0 --min-lp-tok -4.0 \
    --mined-limit 40000 --compose 30000

# 3) дообучение от прежней модели-собеседника (~1 ч на 4 ядрах CPU)
LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libjemalloc.so.2 \
python train_chat.py sft --base slr_net_chat_ru_mini.npz --data data/chat_reason --out runs/chat_reason \
    --seq-len 256 --batch-size 16 --epochs 1.0 --lr 3e-4 --warmup 50 --eval-every 300 --compile

# 4) проверка до/после и упаковка
python train_chat.py eval --ckpt slr_net_chat_ru_mini.npz runs/chat_reason/best.pt --data data/chat_reason --json runs/eval.json
python train_chat.py export --ckpt runs/chat_reason/best.pt --out slr_net_chat_ru_mini.npz

# 5) гипотезы и самопроверка при проверке (без дообучения)
python train_chat.py eval --ckpt slr_net_chat_ru_mini.npz --data data/chat_reason --rerank 8
```

Журналы обучения, настройки и все ответы моделей на проверке — в
[`training/chat_reasoning/`](training/chat_reasoning/).
